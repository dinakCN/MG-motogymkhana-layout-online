## Как это устроено

**Система показывает протокол, а не ведёт его.** Результаты приходят
со страницы этапа на gymkhana-cup.ru, где секретарь соревнований ведёт
протокол по ходу дня. Сервер опрашивает её раз в несколько секунд
и рассылает изменения в кадр: сайт — единственный источник правды.

Отсюда разделение обязанностей на две параллельные работы:

| Кто | Что делает | Где работает |
|---|---|---|
| **Секретарь** | вносит время заездов и штрафы по факту финиша | сайт с протоколом этапа |
| **Оператор графики** | выводит в кадр спортсмена, таблицу, паузу, награждение | пульт `/control` |

Оператор графики вызывает райдера по номеру и переключает сцены — места,
лучшее время и рейтинги пересчитываются сами. Совмещать обе работы можно,
и на небольшом старте один человек справится, но в эфире они спорят
за время: пока ищешь строку в протоколе, в кадре некому вывести
следующего участника.

Поля для ввода времени в пульте есть — блок «Аварийная правка результата»:
резерв на случай, когда результат не подтянулся с сайта. **Вести им
протокол не следует** — два источника правды неизбежно разойдутся.

**Требование к организаторам одно:** результат должен попадать на сайт
сразу после заезда, а не пачками в конце серии. Иначе весь день в кадре
будет стоять таблица получасовой давности.

**Тонкий слой, а не ещё одна система.** Своей базы и своего протокола
графика не заводит — она садится на то, что на площадке уже есть:
результаты берутся прямо со страницы этапа, живое время заезда —
с секундомера на трассе по общей сети, кадр отдаётся обычной веб-страницей.

Репозиторий обезличен: название соревнований, логотип, афиша и схема
трассы — заглушки. Всё своё подставляется в одном файле и одной папке,
без правки кода.

## Что должно быть на площадке

Проверить до того, как заниматься настройкой: без первых трёх пунктов
система не поедет.

| | Что | Зачем |
|---|---|---|
| 1 | **Ноутбук** с Node.js 18+ | на нём поднимается сервер графики и, если выбран NDI, работает OBS |
| 2 | **Интернет** на этом ноутбуке | опрос страницы этапа. Отвалится — в кадре застынет таблица получасовой давности |
| 3 | **Приёмник трансляции**: микшер, отдельная машина с vMix, стриминговая станция | забирает готовый кадр и кладёт его поверх картинки с камер |
| 4 | **Общая сеть площадки** — Wi-Fi и провода | связывает ноутбук, приёмник и таймер. [Схема и ограничения](docs/setup.md#этап-4-сеть-площадки) |
| 5 | **Таймер на трассе** — необязателен | живой отсчёт во время заезда. Без него в зоне времени стоит результат первой попытки |

Секретарь работает со своего устройства и к системе графики
не подключается: ему нужен только доступ на сайт с протоколом.

## Запуск

```bash
npm install
npm run build            # собрать статику: один раз и после правки кода в app/
STAGE=670 npm start      # 670 — номер этапа на сайте; http://localhost:4300
```

`/overlay` — кадр графики, `/control` — пульт оператора. Без указанного
этапа сервер намеренно не поднимется: система, которая работает, но
не получает данных, хуже несобравшейся. Постоянный этап вписывают
в `event.config.js` — этап 6.

## Порядок подготовки

Система готовится семью этапами. Первые четыре — оборудование, программы
и сеть — вынесены в отдельный документ: они делаются один раз и заранее,
их не перечитывают перед каждым стартом.

| | Этап | Где |
|---|---|---|

| 2 | Плагины — DistroAV NDI | [docs/setup.md](docs/setup.md#этап-2-плагины) |
| 3 | Как графика попадает в эфир — веб-источник или NDI | [docs/setup.md](docs/setup.md#этап-3-как-графика-попадает-в-эфир) |
| 4 | Сеть площадки — схема и ограничения | [docs/setup.md](docs/setup.md#этап-4-сеть-площадки) |

| 6 | Настройка под своё соревнование — `event.config.js` | ниже |
| 7 | День эфира — порядок действий | ниже |

Если система уже разворачивалась на прошлом старте, из подготовки
остаются этапы 5–7: прибор, конфиг и порядок дня.

## Этап 5. Таймер

Секундомер на трассе даёт живой отсчёт во время заезда. Система забирает
показания по сети сама, второй машины и моста в схеме нет.

**Требование к прибору одно, и его стоит выяснить у производителя
до закупки:** таймер или табло должны уметь работать **клиентом в чужой
Wi-Fi сети**. Приборы обычно живут в двух режимах — либо раздают
собственную точку доступа (и тогда они изолированы от интернета и всего
остального), либо подключаются к существующей сети. Нужен второй.
С ним все проблемы решаются один раз: прибор заходит в общую сеть
площадки, туда же, где сервер, и оказывается доступен без ухищрений.

Порядок настройки зависит от производителя: у одних режим переключается
в веб-интерфейсе прибора, у других — кнопками на самом устройстве.
Смысл везде один — выбрать клиентский режим, указать имя сети площадки
и пароль.

**Критично: закрепить за прибором постоянный IP-адрес** — привязкой
к MAC-адресу в роутере. Иначе после перезагрузки роутера адрес сменится,
и строка `timer` в конфиге станет враньём.

Требования к сети площадки со стороны прибора:

| Требование | Почему |
|---|---|
| **2,4 ГГц** | 5 ГГц большинство таких приборов не видит физически. Одно имя на оба диапазона обычно проходит |
| **Ширина канала 20 МГц** | у приборов бывают свои пожелания по частотам и ширине канала — узнавать у производителя. У нас работала ширина 20 МГц, не 40 |
| **WPA2 или открытая** | WPA3-only прибор не осилит. Смешанный WPA2/WPA3 обычно проходит |
| **Без портала со входом** | гостевую сеть со страницей авторизации прибору нечем пройти |
| **Изоляция клиентов выключена** | иначе оба в сети, а ноутбук прибора не видит |
| **Имя и пароль латиницей** | настройки уезжают в прибор строкой |
| **Уверенный сигнал в точке установки** | главный практический риск: прибор стоит у трассы. См. [ограничения сети](docs/setup.md#известные-ограничения) |

Найденный адрес вписывается в `event.config.js`:

```js
timer: '192.168.1.97',
```

Проверка после старта: в журнале сервера — `[timer] прибор отвечает`,
в строке состояния пульта — «таймер на связи». Молчание дольше трёх
секунд зажигает красное «ТАЙМЕР НЕ ОТВЕЧАЕТ»; эфир при этом не рвётся.

**Таймер необязателен.** Пустое поле `timer` — рабочее состояние,
а не поломка. Разово погасить прибор: `TIMER=0 npm start`. Трафика прибор
ест мизер: десяток байт три раза в секунду.

## Этап 6. Настройка под своё соревнование

Всё, что меняется от старта к старту, лежит в
**[`event.config.js`](event.config.js)** в корне. Это единственный файл,
который правят перед эфиром. После правки — перезапуск сервера;
**пересобирать не нужно**: настройки живут на сервере и приезжают в пульт
и в кадр по WebSocket.

```js
eventTitle: 'Кубок города по мотоджимхане 2026',  // шапка кадра
stage: '677',                                     // этап на сайте gymkhana-cup.ru
timer: '192.168.1.97',                            // прибор на трассе, можно пусто
trackMap: '/assets/track-map.svg',                // схема трассы, можно пусто
logo: '/assets/logo.png',                         // эмблема с надписью
logoMark: '/assets/logo-mark.png',                // знак без надписи
awardGroups: [ … ],                               // группы награждения
```

### Страница протокола

`stage` — страница этапа на сайте, откуда берутся результаты. Задаётся
**номером или полной ссылкой**, как удобнее:

```js
stage: '677',
stage: 'https://gymkhana-cup.ru/competitions/stage?id=677',
```

Из номера адрес собирается по шаблону `stageUrlTemplate` — его правят,
если сайт переехал или протокол ведут на другом ресурсе. Номер система
достаёт из ссылки сама: им подписан пульт и назван файл состояния.

Пока в файле вписан боевой этап, пульт подсветит жёлтым всё, что ему
не равно, — забыть, что сервер поднят на архивном этапе, невозможно.
В шаблоне поле пустое, и сравнение появится вместе с боевым этапом.

Опрос идёт раз в `pollInterval` мс — в шаблоне 5000. Сбой опроса ничего
не затирает: в кадре остаются последние хорошие данные, а индикатор
свежести в пульте желтеет.

### Логотип, схема трассы, афиша

Файлы кладут в `public/assets/` и указывают путём от корня сайта
(`/assets/…`); принимается и полная ссылка на чужой хост. Папка отдаётся
как есть — **пересобирать статику не нужно**, достаточно перезапустить
сервер.

| Файл | Что это | Где в кадре |
|---|---|---|
| `logo.png` | эмблема с надписью | заставка (138 px) |
| `logo-mark.png` | тот же знак без надписи | пауза, награждение, жучок в углу |
| `track-map.*` | скан схемы трассы | сцена «Схема», клавиша `8` |
| `poster.jpg` | афиша 640×960 | баннеры-заставки |

Логотипу нужен PNG с прозрачным фоном: под эмблему подкладывается светлая
плашка, и белый прямоугольник вокруг был бы виден. `logoMark`
необязателен — без него везде встанет `logo`.

Схема — картинка (PNG, JPG, SVG), **не PDF**: страницу рисует браузерный
движок, просмотрщика PDF там нет. Размер не важен: скан A4 на 300 dpi
сервер сам уменьшит до 1528×1080. Пустое поле `trackMap` гасит сцену
и клавишу `8`.

Афиша идёт не в оверлей, а в полноэкранные баннеры-заставки, которые
снимают из шаблона `public/assets/banners/banner.html` — см.
[инструкцию рядом](public/assets/banners/README.md).

### Группы награждения

Спортивные классы от старта к старту не меняются, а **группировки меняются
всегда**: одно положение сводит медали к «Спортсменам, Любителям,
Новичкам», другое добавляет «Девушек», «Ветеранов», «Круизер», «SB».
Поэтому в системе нет ни одного зашитого названия — весь состав
награждения читается из `awardGroups` и сверяется с блоком «Классы
награждения» на странице этапа:

```js
awardGroups: [
  { name: 'Спортсмены', classes: ['A', 'B', 'C1', 'C2', 'C3', 'D1'] },
  { name: 'Любители',   classes: ['D2', 'D3'] },
  { name: 'Новички',    classes: ['D4', 'N'] },
  { name: 'Девушки',    classes: [] },   // набирается руками в пульте
  { name: 'Круизер',    classes: [] },
  { name: 'SB',         classes: [] },
],
strictGroups: true,   // участник ровно в одной группе; false разрешает двойной зачёт
```

Групп может быть сколько угодно, называются они как в положении.
Названия попадают в кадр как есть — в заголовок церемонии, в секции
итоговой таблицы, в топ рядом с карточкой заезда.

#### Два вида групп

**Выводимые из протокола** — те, что собираются по классу: `classes`
перечисляет спортивные классы, и участники раскладываются сами, без
единого клика.

**Невыводимые** — те, о которых в протоколе нет данных: `classes: []`.
Круизер и SB определяет мотоцикл, «Девушек» и «Ветеранов» — сам участник,
а в колонке класса на сайте этого нет и не будет. Такие группы объявляют
пустыми и набирают галочками в пульте: в строке участника открывается меню
групп, отметка ставится кружком. Пустой `classes` — не ошибка, а способ
сказать «эту группу собирает оператор».

Группа без единого участника в кадр не идёт: объявленный на весь сезон
«Круизер» до первой пометки просто не показывается, вместо пустой плашки
в эфире.

#### Дополнительный зачёт поверх классового

«Девушки» и «Круизер» — обычно не замена основному зачёту, а добавка
к нему: девушка едет и в «Любителях», и в своём зачёте. Для этого нужен
режим `strictGroups: false` — тогда галочка **добавляет** группу,
не отнимая посчитанную по классу. В строке участника встанет бейдж
`Любители` с припиской `+1`: показывается группа, которая выше в конфиге,
а счётчик говорит, что зачётов больше одного.

При `strictGroups: true` группы ведут себя как радиокнопки: отметка
переносит участника, а не добавляет зачёт. Режим общий на весь этап
и задаётся положением соревнований, а не оператором в эфире.

#### Правила, о которые можно споткнуться

- **Класс попадает ровно в одну группу.** Класс, вписанный в две, — опечатка: участники уедут в первую. Сервер ловит это при старте и пишет в журнал `[mg] ВНИМАНИЕ: класс D2 есть и в «…», и в «…»`.
- **Имя «Вне групп» занято системой.** Так называется место сбора тех, чей класс не нашёлся ни в одном списке. Появился этот пункт в пульте — кого-то потеряют на награждении: класс дописывают в нужную группу.
- **Порядок в конфиге значит две вещи** — порядок секций в таблице и порядок церемонии, а ещё приоритет: если у участника два зачёта, в карточке заезда покажется тот, что выше в списке.
- **Смена состава между этапами безопасна.** Пометки на группы, исчезнувшие из конфига, отсеиваются сами: бейдж покажет «вне групп», а не название несуществующей группы.
- **Имена не должны дублироваться** — две одинаковые строки дадут в пульте два неразличимых пункта; сервер предупредит и об этом.

Полная логика — три состояния пометки, конфликты, подиум, счётчики —
в [docs/award-groups.md](docs/award-groups.md).

### Переменные окружения

Разовое изменение без правки файла — на репетиции и когда лезть в конфиг
перед эфиром боязно:

| Переменная | Что делает |
|---|---|
| `STAGE=670` | другой этап: номером или ссылкой |
| `PORT=4310` | другой порт |
| `HOST=127.0.0.1` | закрыть вход снаружи |
| `TIMER=192.168.1.97` · `TIMER=0` | адрес прибора · погасить таймер |
| `TRACK_MAP=/assets/x.png` · `TRACK_MAP=0` | другая схема · погасить сцену |
| `LOGO=` · `LOGO_MARK=` | другие логотипы |
| `RESULTS_BY_GROUP=1` | таблица стартует в разрезе по группам |
| `SHOW_RUN_TIME=0` · `SHOW_CLASS_TOP=0` | убрать из заезда зону времени · топ-3 |

Есть ещё `POLL_INTERVAL`, `TIMER_POLL` и `HIGHLIGHT_TIMEOUT` — те же поля
конфига. Названный переменной тумблер сильнее выбора оператора в пульте:
тот, кто пишет его перед `npm start`, знает, чего хочет от этого запуска.

## Этап 7. День эфира

Сеть, тракт до микшера, OBS и таймер готовятся заранее — по
[подготовке площадки](docs/setup.md) и [чеклисту](docs/broadcast-checklist.md),
не в день эфира. В день эфира остаётся короткий порядок:

1. Развернуть и поднять сеть, проверить, что таймер получил свой закреплённый адрес.
2. `npm start`. В журнале — строка с боевым этапом и **`[timer] прибор отвечает`**: она значит, что прибор действительно ответил, а не просто вписан в файл.
3. Открыть пульт. Счётчик «обновлено N с назад» тикает, рядом значится **«таймер на связи»**, в строке состояния — нужный этап без жёлтой плашки.
4. Проверить, что графика доехала до приёмника выбранным путём ([этап 3](docs/setup.md#этап-3-как-графика-попадает-в-эфир)), и прощёлкать все сцены, сверяя с превью — чип **«▸ кадр»** в строке состояния.
5. Выставить «Момент дня» на текущий отрезок программы: от него зависит текст на паузе.
6. Убедиться, что секретарь вносит результаты по ходу дня и они доезжают в кадр.

## Пульт и сцены

**Восемь сцен**, клавиши `1`–`8`:

| | Сцена | Что в кадре |
|---|---|---|
| `1` | Таблица | итоговые результаты, по классам или по группам награждения |
| `2` | Заезд | карточка райдера, живое время с таймера, топ-3 его группы |
| `3` | Хайлайт | нижняя треть, гаснет сама через `highlightTimeout` |
| `4` | Пауза | «идут заезды», «перерыв», «готовимся к награждению» |
| `5` | Награждение | подиум группы целиком или по одному месту |
| `6` | Заставка | тихий экран с логотипом, закрывает кадр целиком |
| `7` | Чистый кадр | прозрачная накладка: только название и логотип поверх камеры |
| `8` | Схема трассы | скан во весь кадр, пока комментатор разбирает трассу |

Простое правило для двух заглушек: камеру видно — `7`, камеру видеть
не надо — `6`.

**Главный жест:** набрать номер участника и нажать Enter — карточка уйдёт
в эфир. Набор сначала заполняет предпросмотр, поэтому следующего райдера
готовят прямо во время заезда предыдущего. Поиск работает и по ФИО:
у части участников номеров нет.

| Клавиша | Действие |
|---|---|
| `1`…`8` | сцена |
| `/` | курсор в поле номера |
| номер + `Enter` | вывести райдера в эфир |
| `T` | зона времени — включить или погасить |
| `G` | таблица: по классам ↔ по группам награждения |
| `S` | сход: слово вместо времени до конца заезда |
| `Esc` | закрыть меню; иначе — убрать фокус и скрыть хайлайт |

Буквы ловятся по клавише, а не по символу, — работают и в русской
раскладке.

**Список участников** во всю правую колонку: сгруппирован по классам,
с фильтрами «без результата», «вне групп», «неявки» и по каждой группе
награждения. Красная точка — тот, кто сейчас в кадре.

**Неявки.** С сайта они не приходят никак: у неприехавшего просто нет
прокатов — ровно как у того, кто ещё не стартовал. Оператор отмечает его
кружком, и отмеченный исчезает из кадра целиком: из таблицы, из топ-3,
с подиума, из счётчиков. Появился результат — участник возвращается сам.

**Живое время.** Пока прибор считает — `ЗАЕЗД 00:20`, на финише — точный
результат и разница с первой попыткой. Клавиша `S` ставит «сход»: судья
остановит секундомер и на сходе, но это время не результат, и в кадр ему
нельзя.

**Живучесть.** Состояние переживает перезапуск сервера
(`state.<этап>.json`, у каждого этапа свой файл), хайлайт, повисший
в момент падения, снимается сам.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| Индикатор свежести пожелтел или покраснел | Опросчик не получает данные. Оверлей показывает последние хорошие — эфир не рвётся. Проверить сеть и строки `[poller]` в журнале |
| Обе страницы пустые | Не собрана статика: `npm run build` |
| Сервер не стартует и просит этап | В `event.config.js` пусто поле `stage`. Вписать номер или запустить с `STAGE=…` |
| Участник пропал из таблицы, хотя он на площадке | Стоит отметка «не приехал». Снять кружком (фильтр «неявки»); вывод в эфир снимает её сам |
| В таблице «незачёт», «сход» или зачёркнутое время | Так и должно быть: в зачёт идёт только пройденная и засчитанная попытка |
| Результат участника не подтянулся с сайта | Развернуть «Аварийная правка результата» и вписать вручную — формат как в протоколе, `01:23.72`. Правка держится, пока её не снимут кнопкой |
| Красное «ТАЙМЕР НЕ ОТВЕЧАЕТ» | Прибор молчит дольше трёх секунд. Эфир не рвётся — зона времени покажет время первой попытки. Частая причина: роутер перезагрузился и выдал прибору другой адрес |
| Сервер упал | `npm start` — состояние и данные поднимутся из файла этапа |
| `EADDRINUSE :4300` | Сервер уже запущен в другом окне: пульт и оверлей подключаются к одному |

## Разработка

```bash
npm test          # парсер, состояние, опросчик, арифметика, группы, явка
npm run test:watch
npm run dev       # vite для правки app/
```

Парсер таблицы покрыт тестами на сохранённом HTML реальных этапов
(`test/fixtures/`) — он единственное место, которое может внезапно
сломаться из-за смены вёрстки на чужом сайте, и проверяется без сети.

Если сайт поменял таблицу:

```bash
npm run fixture          # скачать свежую страницу боевого этапа
npm run fixture -- 670   # или другого — номером либо ссылкой
npm test                 # упавшие тесты покажут, что именно разъехалось
```

Правится `LAYOUT` в начале `server/parser.js` — селектор таблицы, порядок
колонок, цвета классов. Подробнее — в
[ARCHITECTURE](ARCHITECTURE.md#парсер-сломался-сайт-поменял-вёрстку).

## Доработки

Лицензия разрешает форкнуть репозиторий и делать что угодно, но просьба
такая: **если доработка получилась полезной — открывайте pull request.**

Система писалась под мотоджимхану, и её ценность прямо зависит от того,
сколько стартов через неё прошло. Каждое соревнование приносит своё:
другой состав групп награждения, другой таймер, другая схема сети,
сцена, которой не хватило. Всё это стоит вернуть в общий репозиторий —
тогда следующий организатор получит систему, которая уже умеет то, что
вы для себя доделали.

Десяток форков, разошедшихся по мелким правкам, не даёт сообществу
ничего: каждый чинит одно и то же в одиночку и заново. Один репозиторий,
который развивается концептуально, — даёт.

Присылать стоит и то, что не код: замечания к инструкции, схему сети,
которая сработала на вашей площадке, список граблей. Это ровно та часть,
которую невозможно вывести из исходников.
