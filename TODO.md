## Главное правило зачёта

**В итоговое время идёт только пройденная и засчитанная попытка: её время
из протокола плюс штраф, если он есть. Больше ничего.**

Не идёт в зачёт ничего из этого:

| Случай | В протоколе | В кадре |
|---|---|---|
| Незачёт — трасса пройдена, результат не засчитан | время зачёркнуто | то же время, зачёркнутое |
| Сход — заезд не завершён | `59:59.99` | «сход» |
| Не стартовал | пусто | «—» |
| Все попытки без зачёта, но трассу проходил | мест нет | «незачёт» |

Из этого следует остальное: сошедшие и незачтённые не получают мест,
не попадают в топ-5 класса и на подиум награждения, а лучшее время
считается только по засчитанным попыткам.

Правило закреплено тестами (`test/format.test.js`, блок «в зачёт идёт
только засчитанная попытка») и сверено с протоколом четырёх прошедших
этапов. Аварийная правка его не обходит: вписать время незачтённой
попытке можно, но в зачёт оно не пойдёт — пульт об этом предупреждает.

## 3. Настройки OBS → Видео

- [x] Базовое (канвас): 1920×1080
- [x] **Выходное (масштабированное): 1920×1080** — исправлено с 1280×720. NDI отдаёт именно выходное разрешение, в 720p мелкие цифры в таблице результатов поплыли бы
- [ ] **FPS: 25** (сейчас 50). Решено 05.08.2026 ради Wi-Fi — раздел 6

Почему 50 больше не нужны: **OBS вообще не видит камеру**. Плавность
панорам за мотоциклом — забота vMix, у него свой тракт. OBS рисует текст и
плашки, и 50 кадров тут не покупают ничего, а стоят ровно вдвое по сети.

Почему именно 25, а не 30: 25 **ровно делит 50**, каждый кадр оверлея
показывается в программе дважды без дробного пересчёта. При 30 против 50
получилось бы неровное 5:3 и подёргивание на движении — хуже, чем 25.

Цена: анимации оверлея (появление карточки, затухание хайлайта) станут
двадцатипятикадровыми. На таблице результатов незаметно, живой отсчёт
таймера планируется в целых секундах и не страдает вовсе.

Порядок правки тот же, что у цветового формата — поля заблокированы, пока
активен выход:

1. Инструменты → «Настройки DistroAV NDI» → снять **«Главный выход»** → OK
2. Настройки → Видео → **Общие значения FPS: 25** → Применить
3. Вернуть **«Главный выход»** → OK

- [ ] У источника «Браузер» снять **«Использовать пользовательскую частоту кадров»** (сейчас включена, 50). Без этого браузер продолжит рисовать 50 кадров в канвас на 25 — впустую жжёт процессор, и при каждой смене FPS придётся помнить про вторую настройку

#### Прозрачность в vMix — два обязательных шага

Микшер работает на **vMix**, инструкция от их команды: добавить NDI-источник,
выбрать макбук, «прозрачность подхватится сама». Подхватится, но только
после двух изменений — по отдельности ни одно не работает:

- [x] **Настройки → Расширенные → Видео → Цветовой формат: `BGRA`** (было `NV12` — YUV 4:2:0, в нём физически нет альфа-канала). Перепроверено по документации: ни один другой формат OBS альфу в NDI не несёт. Поля блокируются, пока активен NDI-выход, поэтому порядок был такой: снять «Главный выход» → сменить формат → вернуть «Главный выход»
- [ ] **Сказать команде vMix до проверки:** у выхода vMix фон по умолчанию **чёрный**. Прозрачный NDI-источник надо класть **поверх другого источника** — Overlay-каналом или слоем в Multiview. Соло, отдельным входом, он выглядит чёрным прямоугольником, и это не поломка. Иначе посмотрят соло, увидят чёрное поле и решат, что прозрачность не работает
- [x] **Снят глазок с источника «Цвет»** в сцене «MG». Зелёная подложка — непрозрачный слой на весь кадр; пока она видима, прозрачности не будет ни при каком формате. Не удалена: пригодится, если придётся откатиться на кеинг

Признак, по которому видно, что дело именно в формате: при снятой зелёной
подложке и NV12 фон в приёме **чёрный**, а не прозрачный. После перехода на
BGRA он должен стать прозрачным — это и есть проверка, ходить за ответом
к vMix не нужно.

- [x] **`NDI источник` удалён** — и из сцены «MG», и из коллекции целиком. Был замкнутый контур: программа принимала собственный выход внутрь себя, за один прогон 145 просевших кадров из 4986 (2,9%) по `rendering lag/stalls`
- [ ] Если приём понадобится проверять снова — заводить отдельную сцену «Тест приёма», программой оставлять «MG», а перед эфиром эту сцену удалять: при одной сцене промахнуться некуда
- [ ] «Fix alpha blending» включать **только** если после BGRA у плашек полезет тёмная кайма по скруглённым краям или потемнеют полупрозрачные подложки. Заранее, вслепую — испортит нормальную картинку

Настройки в свойствах NDI-источника — это параметры **приёма**, на боевом
тракте их задаёт vMix у себя. На нашей стороне они влияют только на местную
проверку. Для проверки альфы важно, чтобы пропускная способность стояла
«Самый высокий».

Проверить, что формат применился:

```bash
L=$(ls -t ~/Library/Application\ Support/obs-studio/logs | head -1)
grep -A4 "video settings reset" ~/Library/Application\ Support/obs-studio/logs/"$L" | tail -5
```

Ждём `format: BGRA` вместо `format: NV12`.

**Чем платим:** альфа добавляет к потоку около 25%. При отдаче по Wi-Fi это
уже существенно — см. раздел 6, где расписано, чем жертвовать и в каком
порядке, если канал не потянет. Отказ от альфы стоит в этом списке вторым,
после снижения FPS.

**Имя, которое увидит vMix** — не просто `MG-OVERLAY`, а целиком:

```
MACBOOK-PRO-2SHSH913424.LOCAL (MG-OVERLAY)
```

Команде называть эту строку полностью, иначе будут искать.

**Осторожно с петлёй:** NDI-источник, направленный на собственный выход,
в сцене «MG» оставлять нельзя — это обратная связь. Как разовая проверка
приёма — нормально, но потом убрать.

Названия в инструкции команды устарели, на суть не влияет: obs-ndi теперь
называется DistroAV, «NDI Output Settings» — «Настройки DistroAV NDI».
Установка и Main Output у нас уже сделаны, эти шаги можно пропустить.

### Сценарий Б. По HDMI — запасной

HDMI-порт на M3 Pro встроенный, переходник не нужен. Идея простая: OBS
выводит **полноэкранный проектор программы** на HDMI-дисплей, а микшер
видит этот «монитор» как источник.

**Железо и кабель**

- [ ] Длина кабеля до микшера. За 10–15 м пассивный HDMI на 1080p50 уже может не дотянуть — нужен активный или оптический
- [ ] Приёмник должен отдавать корректный **EDID**. Некоторые платы захвата и конвертеры этого не делают, и тогда Мак либо не увидит устройство, либо не предложит 50 Гц. Лечится EDID-эмулятором — если такое всплывёт, железку надо искать заранее, а не 08.08

**Настройки macOS → Мониторы**

- [ ] Разрешение — ровно **1920×1080**. Брать из списка разрешений, «Выглядит как» не трогать: там масштабированные режимы, Мак начнёт скейлить
- [ ] Частота обновления — **50 Гц**, не 60. Канвас после раздела 3 идёт на 25 fps: в 50 Гц каждый кадр показывается ровно дважды, в 60 Гц пришлось бы неровное 12:5 с подёргиванием
- [ ] HDMI-дисплей **не делать главным**: в «Расположении» белая полоска строки меню должна остаться на встроенном экране, иначе меню уедет поверх эфирной картинки
- [ ] Если по краям чёрные рамки или картинка обрезана — Underscan/Overscan в настройках этого дисплея

**OBS**

- [ ] Правый клик по области предпросмотра → **«Полноэкранный проектор (программа)»** → выбрать HDMI-дисплей. Именно «программа», не «предпросмотр»
- [ ] Убедиться, что в статусбаре OBS держится **25.00 / 25.00 FPS** без просадок

**Гигиена системы**

- [ ] Включить «Не беспокоить» — баннер уведомления в эфире вылезет поверх проектора
- [ ] Заставка и сон отключены (раздел 7 — уже сделано)
- [ ] Мышь на этот экран не заводить: проектор курсор не прячет

**Что уточнить у микшера**

- [ ] **1080p50 или 1080i50?** Мак отдаёт только прогрессив. Если вход вещательный и ждёт чересстрочный — нужен конвертер, искать до 08.08
- [ ] **Зелёный под кеинг или fill+key?** Через HDMI альфу не передать в принципе, только кеинг. Фон в сцене — чистый `#00FF00` (цифровой зелёный, не вещательный `#00B140`), назвать им точный цвет
- [ ] Нужен ли по HDMI ещё и звук. Оверлей беззвучный, но если ждут звук — вывод надо отдельно назначить

**Риск, о котором забывают**

- [ ] Проверить, что будет при переключении входа на микшере. HDMI hot-plug заставляет macOS пересобрать расположение экранов, и полноэкранный проектор может слететь. Если слетает — знать заранее, как поднимать: правый клик → проектор, десять секунд

## 6. Сеть — отдаём по Wi-Fi

Решено 05.08.2026: поток идёт по Wi-Fi, обе машины в общей локальной сети.
Это самое узкое место тракта, и текущее подключение его не выдержит.

### Сколько надо и сколько есть

NDI full-bandwidth для 1080p50 — порядка 105–115 Мбит/с, **с альфой
135–150 Мбит/с**. Причём поток не проседает на статике: NDI High Bandwidth
внутрикадровый, каждый кадр жмётся отдельно. Оверлей девяносто процентов
времени неподвижен и всё равно платит полную цену.

Состояние на 05.08.2026:

```
PHY Mode:      802.11n
Channel:       9 (2GHz, 20MHz)
Transmit Rate: 86 Mbps          ← канальная, не пропускная
```

Реальная отдача 802.11n на 2,4 ГГц при 20 МГц — 30–45 Мбит/с. Разрыв
трёх-четырёхкратный: на этом подключении картинка не поедет вообще.

Проверить текущее подключение:

```bash
system_profiler SPAirPortDataType | grep -E "PHY Mode|Channel|Transmit Rate"
```

### Обязательное

- [ ] **Уйти на 5 ГГц.** В эфире рядом видна точка `802.11a/n/ac/ax, канал 48 (5GHz, 160MHz)`. Чистый 5 ГГц на 80 МГц даёт реальных 300–450 Мбит/с — это разница между «не работает» и «работает». Машина умеет и 6 ГГц: если на площадке будет Wi-Fi 6E, брать его
- [ ] **Снизить FPS до 25** — см. раздел 3. Главный рычаг: срезает поток вдвое, до 68–75 Мбит/с
- [ ] **Выключить AirDrop и Handoff.** Интерфейс `awdl0` сейчас `active`: он периодически уводит радио на другой канал сканировать. На обычной работе незаметно, на потоке в сотню мегабит даёт микрозаикания, которые в эфире читаются как рывок
- [ ] **Выключить VPN** — раздел 6а. На Wi-Fi это критичнее, чем на кабеле: туннель добавляет и накладные расходы, и лишний узел
- [ ] Обе машины в одной подсети. Внимание: рабочая подсеть уже 192.168.**2**.x, а не 192.168.1.x — если микшеру давали старый адрес, переиграть
- [ ] На роутере отключить изоляцию клиентов и гостевые VLAN — через них не проходит mDNS-обнаружение NDI

### Сильно желательное

- [ ] **Ethernet хотя бы на одном конце.** «В одной локальной сети» не значит «оба по воздуху». Wi-Fi полудуплексный и общий: если принимающая машина воткнута в роутер кабелем, беспроводным остаётся один хоп вместо двух, и эффективная ёмкость почти удваивается. Дешевле любых других мер
- [ ] Обе машины поближе к точке, по возможности в прямой видимости
- [ ] Прогнать связку в зале, а не дома: на соревнованиях эфир забьют десятки телефонов, и 5 ГГц там будет не таким чистым

### Если и после этого рассыпается

Порядок жертв — по возрастанию потерь:

1. **FPS 25** (уже в плане) — оверлею почти ничего не стоит
2. **Отказ от альфы**, возврат к зелёному кеингу — минус ~25% трафика, но полезут кайма на скруглениях и съеденные тени
3. **Разрешение 1280×720** — последнее средство: мелкие цифры в таблице результатов поплывут, ради чего мы её и поднимали с 720p

## 7. Питание ноутбука

Эфир ведём с зарядкой — на питании от сети профиль уже правильный
(`sleep 0`, `displaysleep 0`, `lowpowermode 0`). Батарейный настраиваем на
случай, если розетку выдернут.

Заводской батарейный профиль для эфира негоден: сон через минуту простоя,
плюс включённый режим низкого энергопотребления тротлит CPU и GPU.
Через Системные настройки это не лечится — для батареи Apple не даёт галки
«не переходить в режим сна», только `pmset`.

- [x] Настроено 05.08.2026 (крышка открыта — не спит, экран не гаснет, тротлинга нет):

```bash
sudo pmset -b sleep 0 displaysleep 0 disksleep 0 powernap 0 lowpowermode 0
```

- [ ] После эфира вернуть заводские значения:

```bash
sudo pmset -b sleep 1 displaysleep 60 disksleep 10 powernap 1 lowpowermode 1
```

`disablesleep 1` не трогаем: он отменяет сон **глобально**, а не только на
батарее, и нужен лишь при работе с закрытой крышкой. Крышка открыта —
значит не нужен, и закрытие крышки остаётся обычным способом усыпить
машину после эфира.

Проверить, что применилось:

```bash
pmset -g custom          # смотреть блок Battery Power
pmset -g assertions      # кто держит систему бодрой прямо сейчас
```

Неочевидное: пока включён NDI-выход, от сна прикрывает сам OBS — он держит
ассерт `NDI real-time UDP sending`. Если NDI выключат (например, ради
HDMI-тракта), эта защита пропадёт. Поэтому `pmset` делаем **до** того, как
гасить NDI, а не после.
