## Главное правило зачёта

**В итоговое время идёт только пройденная и засчитанная попытка: её время
из протокола плюс штраф, если он есть. Больше ничего.**

Не идёт в зачёт ничего из этого:

| Случай | В протоколе | В кадре |
|---|---|---|
| Незачёт — трасса пройдена, результат не засчитан | время зачёркнуто | то же время, зачёркнутое |
| Сход — заезд не завершён | `59:59.99` | «сход» |
| Не стартовал | пусто | «—» |
| Все попытки без зачёта, но трассу проходил | мест нет | «незачёт» |

Из этого следует остальное: сошедшие и незачтённые не получают мест,
не попадают в топ-5 класса и на подиум награждения, а лучшее время
считается только по засчитанным попыткам.

Правило закреплено тестами (`test/format.test.js`, блок «в зачёт идёт
только засчитанная попытка») и сверено с протоколом четырёх прошедших
этапов. Аварийная правка его не обходит: вписать время незачтённой
попытке можно, но в зачёт оно не пойдёт — пульт об этом предупреждает.

## 1. NDI: runtime и плагин

Порядок важен — сначала runtime, потом плагин.

- [ ] Установить **NDI Runtime** (ndi.video, раздел Tools/SDK — либо ссылка из установщика DistroAV)
- [ ] Установить **DistroAV** (бывший obs-ndi), `.pkg` со страницы релизов github.com/DistroAV/DistroAV — сборка под OBS 30+ и ваш процессор
- [ ] Перезапустить OBS
- [ ] Убедиться, что появилось меню **Инструменты → NDI Output Settings**

Если macOS заблокирует плагин как неподписанный: Системные настройки → Конфиденциальность и безопасность → «Открыть всё равно».

Проверка, что плагин лёг на место:

```bash
ls ~/Library/Application\ Support/obs-studio/plugins/
```

## 2. Разрешения macOS 26

Главная засада свежих macOS: без разрешения локальной сети NDI-источник не увидят на принимающей стороне, и выглядит это как «плагин не работает».

- [ ] Системные настройки → Конфиденциальность и безопасность → **Локальная сеть** → включить OBS
- [ ] Там же: **Камера** — если снимаете через OBS
- [ ] Там же: **Запись экрана** — если захватываете окно или экран

## 3. Настройки OBS → Видео

- [ ] Базовое (канвас): 1920×1080 — уже так, проверить
- [ ] **Выходное (масштабированное): 1920×1080** — сейчас 1280×720. Обязательно: NDI отдаёт именно выходное разрешение, в 720p мелкие цифры в таблице результатов поплывут
- [ ] FPS: 30, если микшер работает в 30. Для мотоджимханы 50/60 выглядит лучше — **согласовать с микшером**, иначе рассинхрон

## 4. Коллекция сцен под эфир

- [ ] Коллекция сцен → Новая, назвать «MG эфир» (ролики Just Dance останутся в старой и мешать не будут)
- [ ] Добавить источник **«Оверлей»** — Источник браузера:
  - [ ] URL: `http://localhost:4300/overlay`
  - [ ] Ширина **1920**, высота **1080**
  - [ ] **Снять** «Отключать источник, когда он не виден» — иначе при переключении сцен рвётся связь с сервером
  - [ ] **Снять** «Обновлять браузер при активации сцены»
  - [ ] Пользовательский CSS оставить как есть — прозрачность у оверлея своя
- [ ] Добавить **камеру** (Устройство захвата видео) и положить её **под** оверлеем

## 5. NDI-выход

- [ ] Инструменты → NDI Output Settings → **Main Output** включить
- [ ] Имя источника задать понятным, например `MG-OVERLAY` — **согласовать с микшером**, они ищут по имени
- [ ] **Preview Output** не включать — лишняя нагрузка на ноутбук

## 6. Сеть

NDI full-bandwidth для 1080p — постоянные 120–160 Мбит/с. По Wi-Fi картинка рассыплется в самый неподходящий момент.

- [ ] Подключить Ethernet (адаптер `en4`)
- [ ] Обе машины в одной подсети
- [ ] На роутере отключить изоляцию клиентов и гостевые VLAN — через них не проходит mDNS-обнаружение NDI

## 7. Проверка связки — до дня эфира, не в день эфира

```bash
STAGE=670 npm start     # репетиция на архивном этапе с результатами
```

- [ ] В OBS источник браузера показывает таблицу результатов поверх камеры
- [ ] Клавиши `1`–`6` в пульте меняют кадр в OBS сразу
- [ ] На принимающей машине в NDI Studio Monitor (или на микшере) виден источник `MG-OVERLAY`
- [ ] Связка отработала полчаса подряд: задержка не растёт, NDI не отваливается
- [ ] Прощёлкан весь пульт: карточка заезда, хайлайт, момент дня, награждение, заставка
