# Чеклист перед эфиром

Что настроить в OBS, в сети и на таймере до того, как начнутся заезды.
Это список галочек: почему так — в [подготовке площадки](setup.md),
про запуск и настройку — в [README](../README.md), про устройство —
в [ARCHITECTURE](../ARCHITECTURE.md).

Команды даны для macOS: на Windows у половины из них свои аналоги,
а смысл тот же.

---

## 1. Видео: 25 fps

- [ ] **Настройки → Видео → Общие значения FPS: 25**
- [ ] Канвас и выход — **1920×1080**. На 720p мелкие цифры в таблице поплывут
- [ ] У источника «Браузер» снять **«Использовать пользовательскую частоту кадров»** — иначе браузер рисует свои 50 кадров в канвас на 25 и впустую жжёт процессор

Почему 25: OBS не снимает камеру, он рисует текст и плашки — лишние кадры
не покупают ничего, а по сети стоят вдвое. Именно 25, а не 30: 25 ровно
делит 50, каждый кадр показывается в программе дважды. При 30 против 50
вышло бы неровное 5:3 и подёргивание.

Поля FPS заблокированы, пока активен выход NDI, поэтому порядок такой:

1. Инструменты → «Настройки DistroAV NDI» → снять **«Главный выход»** → OK
2. Настройки → Видео → **Общие значения FPS: 25** → Применить
3. Вернуть **«Главный выход»** → OK

## 2. Источник и сцена

- [ ] Browser Source на `http://localhost:4300/overlay`, размер **1920×1080**
- [ ] **«Transparent background» включён**
- [ ] **«Shutdown source when not visible» выключен** — иначе при переключении сцен рвётся связь с сервером
- [ ] Под браузером — слой сплошного цвета `#00FF00` на случай отката к кеингу. Скрыть глазком, не удалять
- [ ] **Не заводить NDI-источник в той же коллекции**, куда идёт выход NDI: получится петля и просевшие кадры

## 3. Тракт до микшера

Готовить оба пути: решение может поменяться в последний момент.

### NDI

- [ ] Цветовой формат вывода — **BGRA**. Это единственный формат OBS, несущий альфу в NDI
- [ ] Назвать микшеру имя источника целиком, вида `ИМЯ-МАШИНЫ.LOCAL (ВЫХОД)`. По короткому будут искать
- [ ] Потребовать у приёмника пропускную способность **«Highest»**. NDI отдаёт заодно прокси-поток низкого разрешения, и приёмник вправе взять его — таблица результатов станет кашей из букв
- [ ] **Предупредить микшер:** у их выхода фон по умолчанию чёрный. Прозрачный NDI-источник надо класть **поверх другого** — Overlay-каналом или слоем. Соло он выглядит чёрным прямоугольником, и это не поломка
- [ ] «Fix alpha blending» включать **только** если у плашек полезет тёмная кайма или потемнеют тени. Вслепую — испортит нормальную картинку

**Оверлей прозрачен не всегда, это by design.** Предупредить команду, иначе
на первой же таблице кто-нибудь полезет чинить работающее:

| Режим пульта | Кадр |
|---|---|
| `1` Таблица, `4` Пауза, `6` Заставка, `8` Схема | **непрозрачный целиком** |
| `2` Заезд, `3` Хайлайт, `5` Награждение, `7` Чистый кадр | прозрачный |

### HDMI (запасной)

OBS выводит **полноэкранный проектор программы** на HDMI-дисплей, микшер
видит его как источник.

- [ ] Длина кабеля. За 10–15 м пассивный HDMI на 1080p50 может не дотянуть — нужен активный или оптический
- [ ] Приёмник должен отдавать корректный **EDID**, иначе машина не увидит устройство или не предложит 50 Гц. Лечится EDID-эмулятором — искать заранее, не в день эфира
- [ ] Разрешение ровно **1920×1080** из списка разрешений (масштабирование «выглядит как» не трогать)
- [ ] Частота **50 Гц**, не 60: при 25 fps каждый кадр показывается ровно дважды
- [ ] HDMI-дисплей **не делать главным** — иначе строка меню уедет поверх эфира
- [ ] Правый клик по предпросмотру → **«Полноэкранный проектор (программа)»**. Именно программа, не предпросмотр
- [ ] В статусбаре держится **25.00 / 25.00 FPS**
- [ ] «Не беспокоить» включить, мышь на этот экран не заводить (проектор курсор не прячет)
- [ ] Проверить hot-plug: переключение входа на микшере заставляет систему пересобрать расположение экранов, проектор может слететь

Уточнить у микшера:

- [ ] **1080p50 или 1080i50?** Компьютер отдаёт только прогрессив, для чересстрочного нужен конвертер
- [ ] **Зелёный под кеинг или fill+key?** Через HDMI альфы нет в принципе. Назвать точный цвет фона: `#00FF00` (цифровой зелёный, не вещательный `#00B140`)
- [ ] Нужен ли звук: оверлей беззвучный, но вывод назначается отдельно

## 4. Сеть под поток

Если картинка идёт по NDI через Wi-Fi — это **самое узкое место тракта**.

NDI full-bandwidth 1080p50 — 105–115 Мбит/с, **с альфой 135–150**. Поток
не проседает на статике: каждый кадр жмётся отдельно, неподвижный оверлей
платит полную цену. 802.11n на 2,4 ГГц даёт реальных 30–45 Мбит/с — втрое
меньше нужного.

```bash
system_profiler SPAirPortDataType | grep -E "PHY Mode|Channel|Transmit Rate"
```

Обязательное:

- [ ] **Уйти на 5 ГГц.** На 80 МГц это 300–450 Мбит/с — разница между «не работает» и «работает»
- [ ] **FPS 25** (раздел 1) — срезает поток вдвое, до 68–75 Мбит/с
- [ ] **Выключить AirDrop и Handoff** — `awdl0` периодически уводит радио сканировать соседей, на потоке в сотню мегабит это микрозаикания
- [ ] **Выключить VPN** (раздел 5)
- [ ] Обе машины в одной подсети
- [ ] На роутере отключить изоляцию клиентов и гостевые VLAN — через них не проходит mDNS-обнаружение NDI

Сильно желательное:

- [ ] **Ethernet хотя бы на одном конце.** Wi-Fi полудуплексный и общий: воткнёшь приёмник в роутер кабелем — беспроводным останется один хоп вместо двух, ёмкость почти удвоится. Дешевле любых других мер
- [ ] Обе машины поближе к точке, по возможности в прямой видимости
- [ ] Прогнать связку на площадке: в день соревнований 5 ГГц забьют десятки телефонов

Если и после этого рассыпается — жертвовать по возрастанию потерь:
**25 fps** → **отказ от альфы**, назад на зелёный кеинг (минус ~25 %
трафика, но полезет кайма на скруглениях) → **1280×720** (последнее
средство: поплывут цифры в таблице, ради которых и поднимали разрешение).

## 5. Заглушить машину перед эфиром

```bash
sudo pmset -b sleep 0 displaysleep 0 disksleep 0 powernap 0 lowpowermode 0
sudo ifconfig awdl0 down                    # AirDrop/Handoff: радио перестаёт убегать
```

Плюс выйти из VPN-клиента.

**VPN мешает трижды:** опрос протокола идёт через туннель (отвалится —
в кадре застынет таблица получасовой давности), полный туннель умеет ломать
обнаружение NDI и перехватывать локальные маршруты, то есть дорогу к таймеру.

**Одной команды по `awdl0` мало** — система поднимает его обратно после
перезагрузки и всякий раз, когда просыпается Continuity. Закрыть источник:

- Finder → AirDrop → «Разрешить обнаруживать меня» → **Никому**
- Системные настройки → Основные → **AirDrop и Handoff** → выключить Handoff

Команду давать последней, уже после всех настроек. **«Не беспокоить»**
включать в Пункте управления.

Проверить, что заглушили и что видеотракт в нужном режиме:

```bash
ifconfig awdl0 | grep status                  # ждём: status: inactive
route -n get gymkhana-cup.ru | grep interface # ждём: физический интерфейс, а не utun

L=$(ls -t ~/Library/Application\ Support/obs-studio/logs | head -1)
grep -A6 "video settings reset" ~/Library/Application\ Support/obs-studio/logs/"$L" | tail -7
# ждём: fps: 25/1 и format: BGRA
```

После эфира вернуть как было:

```bash
sudo ifconfig awdl0 up
sudo pmset -b sleep 1 displaysleep 60 disksleep 10 powernap 1 lowpowermode 1
```

AirDrop и Handoff вернуть в Системных настройках — `ifconfig awdl0 up`
этого не делает.

## 6. Таймер

Прибор заходит клиентом в общий wifi площадки, туда же, где сервер.
Второй машины и моста в схеме нет. Устройство и обоснования —
в [плане](superpowers/plans/2026-08-04-timer-bridge.md).

- [ ] **Узнать, есть ли интернет у роутера площадки.** Единственное, что может обрушить схему: таймер будет работать, а таблица застынет — половина кадра живая, половина врёт
- [ ] Проверить на месте: машина одновременно видит таймер и открывает сайт с протоколом

### Порядок настройки

Из коробки прибор обычно раздаёт собственную точку доступа и в общую сеть
сам не зайдёт. Его переводят в клиентский режим штатными средствами
производителя: у одних приборов это веб-интерфейс, у других — кнопки
на самом устройстве.

1. Перевести прибор в клиентский режим, указать имя сети площадки и пароль
2. Перезагрузить прибор, дождаться подключения к сети
3. В роутере закрепить за ним постоянный адрес привязкой к MAC
4. Вписать адрес в `event.config.js` (поле `timer`), перезапустить сервер
5. Если клиентский режим не завёлся — вернуть прибор на его точку доступа: эфир пройдёт без живого отсчёта, зона времени покажет время первой попытки

**После правки клиентского кода обязателен `npm run build`.** Приём
показаний живёт в `app/src/useSocket.js`, то есть в `dist/`. Без сборки
сервер шлёт показания, а кадр их не слышит — выглядит как «таймер сломался».

### Требования к сети площадки

| Требование | Почему |
|---|---|
| **2,4 ГГц** | 5 ГГц большинство таких приборов не видит физически. Одно имя на оба диапазона — обычно нормально |
| **Ширина канала 20 МГц** | пожелания по частотам и ширине канала уточняются у производителя прибора. На 20 МГц связь держалась, 40 МГц — лишний риск |
| **WPA2 или открытая** | WPA3-only прибор не осилит. Смешанный WPA2/WPA3 обычно проходит |
| **Без портала со входом** | Гостевую сеть со страницей авторизации прибору нечем пройти |
| **Изоляция клиентов выключена** | Иначе оба в сети, а ноутбук прибора не видит. Частая настройка гостевых сетей |
| **Имя и пароль латиницей** | Настройки уезжают в прибор строкой JSON |
| **Уверенный сигнал в точке установки** | Главный практический риск: прибор стоит у трассы, антенна слабая. Сорвётся связь — таймер уйдёт из кадра посреди заезда |

**Закрепить адрес за прибором в роутере** (привязка к MAC). Иначе после
перезагрузки роутер выдаст другой, и `timer` в конфиге станет враньём.
Молча это не проходит: через три секунды тишины сервер пишет
`[timer] прибор не отвечает`, а в строке состояния пульта загорается
красное «ТАЙМЕР НЕ ОТВЕЧАЕТ». Пока прибор на связи, там значится
«таймер на связи» — это и есть проверка перед эфиром.

Трафика прибор ест мизер: десяток байт три раза в секунду.

## 7. Проверка связки — заранее, не в день эфира

```bash
STAGE=670 npm start     # репетиция на архивном этапе с результатами
```

- [ ] В OBS источник браузера показывает таблицу результатов поверх зелёной подложки
- [ ] Клавиши `1`–`8` в пульте меняют кадр в OBS сразу
- [ ] Картинка доехала до микшера, кеинг по зелёному чистый: по краям плашек нет каймы, полупрозрачные тени не съедены
- [ ] Если идёт NDI — на принимающей машине источник виден в NDI Studio Monitor
- [ ] Связка отработала полчаса подряд: задержка не растёт, картинка не отваливается
- [ ] Прощёлкан весь пульт: карточка заезда, хайлайт, момент дня, награждение, заставка, схема трассы
- [ ] Состав `awardGroups` сверен с блоком «Классы награждения» на странице этапа
