# Устройство проекта

Документ о том, как система работает и по каким правилам в ней меняют код.
Про запуск и эфир — [README](README.md).

---

## 1. Главное правило

**Мы не ведём протокол. Мы его показываем.**

Протокол ведут организаторы на сайте федерации. Наша система — зеркало:
она забирает готовые данные и превращает их в графику. Из этого следует
всё остальное.

Мы **не считаем** места, лучшее время и рейтинг, если их посчитал сайт.
Разойтись с официальным протоколом в прямом эфире недопустимо: зритель
увидит на экране одно, а в итоговой таблице появится другое. Свой расчёт
включается только там, где у сайта значения нет.

Мы **не даём оператору вводить результаты**. Не потому что он ошибётся,
а потому что два источника правды неизбежно разойдутся — и никто не
узнает, какой из них верный.

## 2. Три звена

```
организаторы          наш сервер              кадр
     │                     │                    │
  вносят           опрашивает раз в 7 с    показывает
результат  ──────▶  разбирает таблицу  ──────▶  оверлей (OBS)
на сайте            держит состояние            пульт (браузер)
```

Единственное звено, требующее интернета, — опрос сайта. Всё остальное
живёт на ноутбуке. Пропала сеть — графика продолжает работать на
последних хороших данных.

**Единый источник правды — состояние на сервере.** Оверлей и пульт не
хранят ничего своего: оба получают одно и то же по WebSocket. Поэтому
они не могут показать разное.

## 3. Что происходит за день

| Время | Что в кадре | Откуда данные |
|---|---|---|
| Первая серия | Карточка райдера, между заездами — таблица | Оператор вызывает райдера по номеру; результаты приходят сами |
| Перерыв | Пауза или заставка | — |
| Вторая серия | То же, метка «Попытка 2» | То же |
| Итоги | Таблица с обеими попытками | Сайт считает лучшее время и места |
| Награждение | Подиум по классам | Из уже разобранной таблицы |

Оператор за весь день **не вводит ни одной цифры**. Он выбирает, что
показать, и когда.

## 4. Инварианты

Правила, которые нельзя нарушать при изменениях. Каждое оплачено
конкретным риском.

**Сбой никогда не затирает данные.** Ни сетевая ошибка, ни сломанная
вёрстка, ни пустой ответ не заменяют участников в кадре. Итерация
пропускается, ошибка уходит в лог. Оверлей продолжает показывать
последнее хорошее состояние.
→ `applyParticipants` в `server/state.js`, тесты в `test/state.test.js`

**Ключ участника — только `athleteId`.** Не номер: номера проставляют
по ходу дня, и в момент простановки ключ бы изменился, а `TransitionGroup`
переанимировал бы таблицу посреди эфира. У кого ссылки на профиль нет —
хеш от ФИО.
→ `server/parser.js`

**Ручные правки переживают опрос.** Они хранятся отдельно от данных
(`state.overrides`) и накладываются после каждого обновления. Иначе
правка стиралась бы через семь секунд — ровно тогда, когда она нужна.
→ `applyOverrides` в `server/state.js`

**Хайлайт возвращает кадр.** Он вставка поверх эфира, а не пункт
назначения: после таймаута сцена возвращается туда, откуда её вызвали.
Иначе через шесть секунд в кадре осталась бы пустота.
→ `showHighlight` / `hideHighlight` в `app/src/control/ControlRoot.vue`

**Состояние переживает перезапуск.** Всё пишется в `state.json` при
каждом изменении. Упавший сервер поднимается той же командой и
возвращает и сцену, и данные.

## 5. Границы файлов

```
server/
  parser.js    HTML → участники. Не знает про сеть
  poller.js    сеть → parser → состояние. Не знает про разметку
  state.js     состояние, команды, сохранение. Не знает ни про то, ни про другое
  index.js     раздача статики и рассылка по WebSocket
  config.js    порт, этап, интервал
```

Разделение не косметическое. **`parser.js` — единственное место, которое
может внезапно сломаться**, потому что зависит от чужой вёрстки. Он
вынесен в чистую функцию именно поэтому: тестируется на сохранённом
HTML без интернета, и его можно чинить, не трогая ничего вокруг.

```
app/src/
  useSocket.js       подключение и переподключение
  shared/format.js   разбор времени, дельты, группировка
  overlay/           то, что видит зритель
  control/           то, что видит оператор
```

`BaseLayer.vue` — общий материал полноэкранных сцен: фон, логотип, место
под содержимое. На нём стоят заставка, пауза и награждение, поэтому фон
описан один раз и сцены не расходятся.

## 6. Как менять

### Парсер сломался (сайт поменял вёрстку)

Самый вероятный сценарий поломки.

1. Сохрани свежую страницу: `curl "https://gymkhana-cup.ru/competitions/stage?id=677" -o test/fixtures/stage677.html`
2. Запусти `npm test` — упавшие тесты покажут, что именно разъехалось.
3. Чини `server/parser.js`, пока тесты не позеленеют.

**Не подгоняй тесты под парсер.** Они описывают реальные данные: 22
участника на этапе 670, Акимов с временем `01:23.72`, участник без
номера, участник без класса. Если тест перестал соответствовать
реальности — сначала убедись, что изменилась реальность, а не парсер.

### Добавить сцену

1. Добавь ключ в `SCENES` (`server/state.js`) — иначе команда будет отвергнута.
2. Создай компонент в `app/src/overlay/`. Полноэкранной сцене дай `BaseLayer`.
3. Подключи в `OverlayRoot.vue`.
4. Добавь кнопку в `SceneTabs.vue` и горячую клавишу в `ControlRoot.vue`.
5. Проверь в браузере — превью в пульте показывает кадр вживую.

### Поменять оформление

Токены — в `app/src/style.css` (оверлей) и `app/src/control/control.css`
(пульт). Палитра системная, из macOS.

Одно ограничение: **в оверлее `backdrop-filter` бесполезен.** OBS
подкладывает видео уже после браузера, размывать нечего. Стекло там
собрано слоями вручную. В пульте блюр настоящий.

## 7. Проверка

```bash
npm test    # 58 тестов, без сети
```

Тесты покрывают то, что должно работать, когда всё плохо: сбой сети,
битый JSON, сломанная вёрстка, пустой ответ поверх хороших данных.

**Тесты не заменяют браузер.** Два самых опасных бага проекта — хайлайт,
не переключавший сцену, и правка, стиравшаяся через семь секунд, — прошли
все тесты и вылезли только при клике мышью. Перед эфиром прощёлкай пульт
руками на `STAGE_ID=670`.

## 8. Чего система не делает

Осознанные границы, чтобы их не пытались расширить по инерции.

- **Не считает результаты** — этим занимается сайт федерации.
- **Не знает стартовый порядок** — в данных его нет, автоматического «следующего участника» быть не может.
- **Не показывает живой таймер** — заезд идёт без секундомера в кадре, напряжение создаёт время соперника.
- **Не работает с телеметрией** — это отдельный пайплайн с GPS-логгером.
- **Не имеет авторизации** — сервер живёт на localhost и никуда не смотрит наружу.
